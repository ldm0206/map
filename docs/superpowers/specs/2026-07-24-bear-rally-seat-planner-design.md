# 无尽冬日熊坑排座静态网页 — 设计文档

日期：2026-07-24
状态：已确认

## 1. 项目概述

为「无尽冬日」（Whiteout Survival）熊集结（熊坑）场景设计的纯静态单页网页工具，用于在地图上为参与集结的玩家排座位。

核心玩法（已与用户确认）：
- 熊坑为集结目标，占地 3×3，全局唯一。
- 旗帜占地 1×1，覆盖以其为中心的 7×7 范围。旗帜可多个，每个有各自的 7×7 覆盖区。
- 所有参与集结的玩家 2×2 主城必须落在至少一个旗帜的 7×7 覆盖范围内。
- 离熊坑越近（欧氏距离）伤害加成越高，因此高优先级玩家座位越靠前（越近熊坑中心）。
- 矿、山、湖为障碍物，其上不能建设建筑。矿 1×1，山/湖形状不限。
- **所有建筑（熊坑、旗帜、障碍、玩家）两两不能重叠**——任何放置操作都必须做冲突检测。

技术形态：纯静态单页 `index.html`（内联 CSS+JS），双击即用，可部署任意静态托管。无构建步骤。唯一外部依赖为可选 CDN（见 §6）。

## 2. 数据模型

一份 `ProjectState` JSON 描述整份项目，导入导出均以此为单位。

```
ProjectState {
  bear: { row, col }            // 熊坑左上角，3×3 占地，全局唯一
  banners: [                    // 旗帜列表，可多个，每个 1×1 有各自 7×7 覆盖
    { id, row, col, fixed }
  ]
  obstacles: [                  // 山/湖/矿
    { id, type: 'mountain'|'lake'|'mine', cells: [[r,c]...] }
  ]
  players: [                    // 玩家优先级列表，顶部=最高优先级
    { id, name, priority, fixed, fixedCell: [r,c]? }
  ]
  placement: {                  // 当前排位结果（玩家id → 2×2左上角格）
    playerId: [row, col]
  }
  mode: 'strict'|'minimal'      // 当前排位模式
  minViewSize: {w, h}?          // 用户可选的最小可视尺寸（扩张只增不减）
}
```

说明：
- 不存储固定 `gridSize`。地图可视尺寸由已放置内容动态计算（见 §3）。
- 熊坑、旗帜用绝对坐标存储，地图扩张时位置不变。
- 优先级由 `players` 数组顺序决定（顶部最高），`priority` 字段为冗余缓存序号。

## 3. 地图自动扩张

地图可视尺寸随玩家摆放自动扩张：
- 视野下界 = 包络（熊坑 3×3 ∪ 旗帜 7×7 覆盖区 ∪ 所有障碍物格 ∪ 所有已落座玩家 2×2 ∪ 所有固定玩家的固定格）的最小外接矩形，再外扩 1 格边距。
- 若用户设了 `minViewSize`，取 `max(包络, minViewSize)`，扩张只增不减，避免排位后地图缩回。
- 扩张向四周进行，已放置内容位置不变。
- 用户也可手动设更大的 `minViewSize` 强制留白。

## 4. 界面与交互

### 4.1 布局（三栏）

```
顶栏：标题 ｜ [加载项目][导出项目][最终图][变动图] ｜ 缩放
左栏：工具栏（单选）— 熊坑 / 旗帜 / 山 / 湖 / 矿 / 手动放玩家 ｜ 撤销/重做
中栏：地图画布（网格、拖放、滚轮缩放、空格+拖拽平移）
右栏：玩家优先级列表（拖拽排序、固定开关、删除）｜ 批量导入名单 ｜ 模式：严格/最小 ｜ [一键排位][清空排位]
```

### 4.2 画布交互

- **熊坑**：初始放地图中心，可拖动整块 3×3 移动；遇障碍/玩家/旗帜冲突则回退并提示。
- **旗帜**：选旗帜工具后点击空格放置**新旗帜**（可放多个）；点击已有旗帜可选中拖动；双击或右键某旗帜切换其 `fixed` 锁定（锁定后该旗帜 7×7 覆盖区高亮边框、不可拖动）。用户可自由设计每个旗帜位置并各自锁定。
- **障碍物**：选山/湖/矿工具后在地图上点击/拖拽涂抹；矿默认 1×1，山/湖可涂任意多格；再点已涂格可擦除。
- **手动放玩家**：选手动排位工具后，从右栏把玩家拖到地图任意可建格；手动放下的玩家自动标记 `fixed`（手动放置=锁定），后续算法不动它。
- **撤销/重做**：所有编辑操作进栈，Ctrl+Z / Ctrl+Shift+Z。
- **全局不重叠**：任何放置/拖动/涂抹操作都必须实时冲突检测——熊坑 3×3、每个旗帜 1×1、每个障碍格、每个玩家 2×2 两两不能重叠；冲突时禁止该操作并红色提示。

### 4.3 玩家优先级列表

- 列表项可拖拽排序，顶部=最高优先级。
- 每项：名字、优先级序号、固定开关、删除。
- 固定开关打开后需在地图指定一格作为该玩家固定格。
- 批量导入：粘贴文本（每行一个名字）自动生成列表。

### 4.4 排位操作

- 模式切换：严格 / 最小修改（单选）。
- 一键排位：按当前模式和优先级在地图上排座。
- 清空排位：移除所有非固定玩家落座。
- 排位后每个玩家格显示玩家名 + 优先级序号。
- 冲突检测：放置操作实时检测重叠，冲突时禁止并红色提示。

## 5. 排位算法

### 5.1 公共：候选格与距离

- **可建格** = 地图内、不在熊坑 3×3、不是任何旗帜格、不是任何障碍物格、未被固定玩家占用的格。
- **候选格** = 所有合法的 2×2 左上角格 `(r,c)`，使得 `(r,c)(r,c+1)(r+1,c)(r+1,c+1)` 四格全部可建。
- **距离** = 玩家 2×2 中心 `(r+0.5, c+0.5)` 到熊坑中心 `(bear.row+1, bear.col+1)` 的欧氏距离。
- **覆盖判定** = 玩家 2×2 完全落在至少一个旗帜的 7×7 覆盖区内（`inCoverage(cell, banners)` = 任一旗帜覆盖即为 true）。

### 5.2 严格模式（贪心逐个分配）

1. 玩家按优先级降序排列；固定玩家已在候选集占好位，跳过。
2. 对每个未固定玩家，遍历剩余可用候选格，选欧氏距离最小者；并列时按 `(row, col)` 字典序取最小，保证确定性。
3. 选中后从候选集移除该格，并移除任何与该 2×2 重叠的候选格。
4. 某玩家找不到合法格 → 报错，标红该玩家，提示容量不足。

复杂度 O(n × 候选格数)，30–100 玩家瞬间完成。

### 5.3 最小修改模式（匈牙利算法）

场景：在已有排位图上增量调整（新增/删除/改优先级），要求移动的玩家数最小，同时高优先级仍尽量靠前。

建模为最小费用二分匹配：
- 左节点：所有未固定玩家。
- 右节点：所有合法 2×2 候选格（固定玩家占用格及其重叠格已排除）。
- 边权 `cost(player_i, cell_j)`：
  - `base = distance(cell_j, 熊坑中心)`
  - 玩家 i 在旧排位有位置，且 `cell_j` 是其旧位置 → `cost = 0`（原地不动）
  - 玩家 i 在旧排位有位置，但 `cell_j` 非其旧位置 → `cost = base + M`（M 为大常数，惩罚移动）
  - 玩家 i 是新增（旧排位无）→ `cost = base`
- 删除的玩家不进入左节点（自然不参与匹配）。
- 固定玩家：直接锁定其格，从候选集移除，不进入左节点。
- 用匈牙利算法求最小总费用匹配；玩家数 > 候选格数则报容量不足。

`M` 足够大时，算法优先不移动已落座玩家，必要时才移动，且移动后仍按优先级尽量靠前。

复杂度 O(n³)，n=100 约 10⁶，浏览器毫秒级。

### 5.4 自动扩张联动

排位时若候选格不足以容纳所有玩家，默认报错并提示用户手动扩张或移障碍；可选开启"自动扩张重试"（向四周扩一格重算），默认关闭。

## 6. 导入导出

### 6.1 数据导入导出（JSON）

- 导出项目：下载 `bear-rally-<日期>.json`，内容为完整 `ProjectState`，可完整还原。
- 加载项目：选 JSON 文件，校验结构后整体替换当前状态（带二次确认，避免覆盖未保存编辑）。
- 轻量导入：粘贴文本或上传纯名字列表，只更新 `players`，不动地图。

### 6.2 图片导出

两张图均用**自绘 canvas** 实现（不依赖 html2canvas 截 DOM，高 DPI 可控、箭头精确）：

- **最终排位图** `seats-final-<日期>.png`：重画地图 + 熊坑 + 旗帜 + 障碍 + 所有玩家格（名字 + 优先级序号）。
- **座位变动示意图** `seats-changes-<日期>.png`（仅最小修改模式排位后可用）：重画地图 + 叠加箭头层，对每个移动过的玩家画从旧位置中心到新位置中心的箭头。颜色编码：
  - 蓝 = 新增玩家
  - 淡绿 = 原地不动（可选显示）
  - 橙 = 移动过的玩家
  - 灰虚线 = 被删除玩家（旧位置标灰，名字加删除线）
  - 金 = 固定玩家
  - 右下角放图例。

导出规格：按地图实际尺寸输出，每格 40px，2x 高 DPI。

## 7. 文件结构

单文件 `index.html`，内联 CSS + JS，JS 内部分模块（IIFE/对象）：

- `Store` — 状态管理 + 撤销/重做栈
- `Renderer` — 画布渲染（网格、熊坑、旗帜、障碍、玩家、7×7 覆盖高亮）
- `Editor` — 工具交互（放置/拖动/涂抹/固定）
- `Geometry` — 候选格计算、距离、冲突检测、地图自动扩张
- `StrictSolver` — 严格模式贪心
- `MinimalSolver` — 最小修改模式匈牙利算法
- `Exporter` — JSON 导入导出 + 图片导出（自绘 canvas）
- `UI` — 顶栏/侧栏按钮绑定、模式切换

无构建步骤，双击即用。

## 8. 非目标（YAGNI）

- 不做多份排位方案对比/历史快照。
- 不做服务器、账号、云同步。
- 不做联盟级别多份地图管理（单份项目即可）。
- 不做伤害数值模拟计算（只排座，不算伤害）。
- 不做自动扩张重试（默认关闭，报错提示用户手动处理）。
